# MyLoto — платформа онлайн-лотерей

**MyLoto** — это веб-платформа для проведения онлайн-лотерей.  
Проект реализован как семестровая работа на ASP.NET Core с использованием Clean Architecture и CQRS.

Система позволяет пользователям регистрироваться, авторизоваться, пополнять баланс, покупать билеты, выбирать числа вручную или случайно, следить за live-розыгрышами и получать выигрыши.  
Модератор может создавать лотереи, управлять их активностью и запускать жизненный цикл тиражей.

# Основной функционал

## Для пользователя

Пользователь может:

- зарегистрироваться в системе;
- авторизоваться по логину и паролю;
- получить JWT-токен;
- просматривать активные тиражи;
- покупать билеты;
- выбирать числа вручную;
- генерировать случайную комбинацию чисел;
- просматривать свои билеты;
- фильтровать билеты по статусу:
  - активные;
  - архивные;
  - выигравшие;
  - проигравшие;
- дарить билет другому пользователю;
- смотреть live-розыгрыш в реальном времени;
- пополнять баланс через Stripe;
- получать выигрыш на баланс.

## Для модератора

Модератор может:

- просматривать все лотереи;
- создавать новую лотерею;
- создавать лотереи разных типов:
  - K из N;
  - Bingo;
- задавать правила выплат;
- ставить лотерею на паузу;
- возобновлять лотерею;
- автоматически запускать генерацию тиражей через Hangfire.

# Архитектура проекта

В проекте используется **Clean Architecture** совместно с **CQRS**.

## Почему выбрана Clean Architecture

В проекте есть сложная бизнес-логика:

- покупка билета;
- проверка возраста пользователя;
- проверка баланса;
- генерация случайных чисел;
- запуск тиража;
- проверка выигрышей;
- начисление призов;
- обработка платежей;
- live-трансляция розыгрыша.

Поэтому важно отделить бизнес-логику от инфраструктуры, базы данных, API и внешних сервисов.

## Почему выбран CQRS

Операции чтения и изменения состояния в проекте отличаются.

Примеры команд:

- регистрация пользователя;
- покупка билета;
- создание лотереи;
- запуск тиража;
- начисление выигрышей;
- пополнение баланса.

Примеры запросов:

- получение активных тиражей;
- получение профиля пользователя;
- получение списка билетов;
- получение live-статуса тиража.

Поэтому проект разделён на:

- **Commands** — изменяют состояние системы;
- **Queries** — только читают данные.

Обработка команд и запросов выполняется через **MediatR**.
